Point-Conditioned Document Parsing

Technical note · Synthetic training page · dense layout revision

End-to-end page parsers emit full-page Markdown, but interactive tools often need only the semantic block under a cursor. Prompting alone rarely suppresses whole-page dumps on busy screenshots.

Fine-tuning with an explicit crosshair cue teaches the model to localize and transcribe a single minimal block while ignoring neighboring columns, side rails, and window chrome.

Training pages should look crowded: navigation, multi-column body, sidebars, and footnotes — not a lonely card floating on blank wallpaper.

Motivation

Synthetic HTML remains the scale path: one source yields pixels, boxes, and Markdown. Real desktops can be added later for distribution shift.

Geometry must track text ink. Full-width heading boxes would place the crosshair beside short titles; Range-based rects fix that mismatch.

Negatives on gutters and chrome map to empty labels so the model learns to abstain.

Screen-domain JPEG and rescale noise approximate capture pipelines used in products.

Checklist

  • Center-biased point sampling inside text-tight boxes
  • Negative points on blank chrome → empty label
  • Conservative bucketed QA before scale-up
  • Stacked desktop windows for occlusion stress

Tables and formulas are serialized from the same HTML source used for rendering, avoiding OCR-as-GT circularity on the synthetic arm.
