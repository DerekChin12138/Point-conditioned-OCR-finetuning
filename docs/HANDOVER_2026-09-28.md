## 2. 本次新增/修复的关键基础设施（必读）

### 2.1 分辨率上限修复（`UnslothVisionDataCollator`）
`resize="min"` + `vision_config.image_size=768` 会把**图像宽度压到 768**（3760×2112 页 → `[1,28,48]` ≈ 336 视觉 token），
`--max-pixels 8294400` 完全无效；而评测/Studio 走 processor **没有这个上限** → train/eval 不一致。

- 修复：`train/unsloth_stage_a.py` 新增 **`--collator-resize {max,min}`，默认 `max`**；分辨率由 `--max-pixels` 控制；
  新增视觉 token 预算告警。**train / `eval/run_*.py` / `marker_studio` 默认对齐到 2048²**。
- 规则：**视觉 token ≈ `max_pixels/1024`**，要求 `max_pixels/1024 + ~2048 ≤ max_seq_length`。
  2880² → ~8100 tok → **`--max-seq-length ≥ 12288`**（8192 会截掉答案）。
- 2880² 实测峰值（最密页）：0.8B bs2 = 5.8GB；2B bs2 = 6.7GB；4B bs1 = 6.6GB。

### 2.2 纯文本样本支持（为「两阶段翻译」准备）
Unsloth collator 原生支持 image/text 混批；我们自己的转换层原先会丢弃无图行，已修：
`sharegpt_to_unsloth` / `run_final_generate_eval` / `point_ocr.infer`（`generate_point_text(image=None)`、`generate_point_batch` 混批）。

### 2.3 上云打包
- `scripts/pack_for_cloud.sh` → 生成 `dist/cloud_pack/{code_files.txt,images.txt}` + 可选 tarball
- `scripts/relocate_paths.py` → **split 里是绝对图片路径**，换机必须重定位（`--old-root … --apply`）
- `scripts/bootstrap_cloud_env.sh` → 装 uv / 配镜像 / sync / 验证
- 详见 `docs/CLOUD_PACKAGING.md`；HF 下载要 `HF_HUB_DISABLE_XET=1`（hf-mirror 不代理 Xet → 401）

### 2.4 长跑守护
`scripts/supervise_08b.sh`（自愈续训）+ `scripts/watch_08b_training.sh`（内存/显存看门狗，可 `WATCH_PAT`/`KILL_PATS` 复用）。
宿主内存教训：`--num-workers 8 --pin-memory --persistent-workers` 长跑会缓慢泄漏（2.5GB→0.7GB available），
**默认改成 `--num-workers 4 --no-pin-memory --no-persistent-workers`**。

### 2.5 编排开关
`scripts/run_08b_full.sh`：Q2 epoch 可用 **`Q2_EPOCHS=0.6`** 覆盖；脚本可重入（跳过已完成阶段、从最新 checkpoint 续）。
`train/run_grpo_hq.sh`：GRPO 一条龙（见 §3.5）。

## 3. 已完成实验与结论（含实测数字）

### 3.1 2B 两轮 SFT（当前最强基线）
| 指标 | 门禁 | 2B Q1 | 2B Q2 |
|---|---|---|---|
| block_hit / source_hit | ≥0.88 | **0.9396** | **0.9140** |
| chrF2 | ≥0.34 | — | **0.3922** |
| both_hit | ≥0.20 | — | 0.1725 ❌（唯一未过） |
| empty（chrome）/ halluc | ≥0.85 / ≤0.10 | 0.9882 | **0.9963 / 0.0037** |
| xml well-formed | ≥0.97 | — | 0.9883 |

分桶（source_hit）：core .960 / multi_frag .800 / semantic_group .814 / real .816。

### 3.2 0.8B 两轮 SFT（768px 口径，**已作废为基线**）
`block_hit 0.9034`（core .955 / mf .691 / sg .968 / real .842）；
Q2 `source_hit 0.8303`、`chrF 0.2978`、`both 0.0767`、`xml_well_formed 0.9453`、`eff_empty 0.9908`、`halluc 0.0092`
（core .893 / mf .693 / sg .734 / **real .500**）。
→ **数字偏低**：训练在 768px、评测在全分辨率（不一致）；报告已加更正说明 `eval/results/q08b_stage_report.md`。

### 3.3 GRPO 历史结论
- 2B GRPO_Q1 v2（2026-09-24）：探针 503 条仅 **25%** 有信号 → 实取 110 条；又被逼降分辨率（1440²/4096）
  → 全面变差（hit −2.4pp、sg −5.8pp）。**结论：本地 8GB 做不了全分辨率 GRPO；纯 SFT 更稳。**
- 详见 `docs/GRPO_Q1_V2.md` §6。**不代表 GRPO 无效**，只代表「8GB + 110 条 + 降分辨率」无效。

### 3.4 4B 本地可行性
加载 + 6 步 SFT（4bit，batch2×accum8，8192）：GPU 峰值 **6419 MiB**、宿主 RAM ~7.0GB、**1.74 s/sample**；
Q1+Q2 全程约 **43h**（或按论文 0.2–0.3 epoch ≈ 9h）。4B GRPO/OPD 本地不可行（要 32GB）。
详见 `eval/results/qwen4b_feasibility/`、`docs/STRATEGY_REVIEW_4B_OPD.md`。

### 3.5 GRPO HQ-200（本次新建，**未跑**）
- 数据（确定性重建，`seed 42`）：`data/splits_grpo_cand{,_q2}/`（1500/120 候选）→
  `data/splits_grpo_{q1,q2}_hq200/`（**200/60**，仅弱点桶：mf/real/sg/long/repeat，**empty 配额 0**）。
- 判据（探针 G=8）：`reward_max_frac ≥ 0.95`（组内有近乎满分轨迹）**且** `reward_std ≥ 0.10`（方差足够）
  且 `0.125 ≤ frac_good ≤ 0.875`；排序 `reward_max_frac → reward_std → 失败模式价值`。
- Q2 默认**定位优先权重** `GRPO_REWARD_WEIGHTS="1.5,0.05,1.0,1.5,1.5,0.75,0.5"`（翻译 0.05≈不管质量），
  probe / compose / train 三处共用（`weights_from_env()`）。
- 入口：`KIND=q1|q2 SIZE=08b|2b|4b bash train/run_grpo_hq.sh {status,cand,seed,probe,compose,dryrun,train,merge,eval,all}`。
- 详见 `docs/GRPO_Q1_HQ200.md`。

### 3.6 OPD（on-policy distillation）调研 + 适配层
- **TRL 0.24 自带 `GKDTrainer`**：`lmbda=1` on-policy + `beta=1` reverse KL = 论文（OvisOCR2）那套；
  它只对 **completion 段**算 logits（全词表也只要 ~250MB），但**不支持视觉输入**（`pixel_values` 被丢）。
- 已实现薄适配层 **`train/unsloth_gkd_vl.py`**（`VLGKDTrainer` + `VLDataCollator` + `perturb_lora` + eos shim）。
- **本地自检通过**：`--selfcheck` → (a) teacher==student 时 reverse KL = **0.000000**；
  (b) 扰动 LoRA 学生 vs 冻结基座 → loss 1.322、grad_norm 93.5。真训练（teacher=4B）需 32GB。
- 推荐在 **Q2 节点**做 OPD，并用 `--mask-translation` 只蒸馏 `<source>`+XML 段。详见 `docs/OPD_PLAN.md`。

## 5. 已知坑（不要再踩）

1. **图像分辨率**：改 `--max-pixels` 必须同步 `--max-seq-length` 和评测侧；2880² 要 12288。
2. **train/eval/Studio 三处 `--max-pixels` 必须一致**，否则 OOD。
3. **GRPO 不能降分辨率**（与 SFT 一致）。
4. **宿主 15GB**：不要 `--num-workers 8 --pin-memory --persistent-workers` 长跑。
5. **HF 下载要 `HF_HUB_DISABLE_XET=1`**，否则 hf-mirror 上 401。
6. **split 里是绝对路径**，换机跑 `scripts/relocate_paths.py`。
7. **空例配额别给 GRPO**（已饱和，0 梯度）。
8. **`both_hit` 是单参考 chrF 的代理**，别当唯一目标（real 桶 chrF 0.605 vs 合成 0.31–0.39 证明差距主要来自参考风格）。
9. **别边跑边改 shell 脚本**（bash 增量读，会执行错乱）；先停再改再跑（脚本可重入）。
10. **参考译文 ~1.9% 繁体**（数据噪声，不是模型问题）。
